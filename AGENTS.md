# AGENTS.md — инструкции для кодинг-агента

## 1. Перед выполнением задачи

Начни с `README.md`. Дальше открывай только то, что нужно для задачи; читать все документы подряд не нужно.

Если документация и код расходятся — покажи расхождение пользователю, не переписывай код молча.
Не меняй нумерацию §3.2–§8 в SDD без обновления docstring.

## 2. Правила

- Новые зависимости — только в `requirements.txt` / `requirements-dev.txt` (файлы зависимостей, не документ).
- Документация: один факт — в одном документе. Не дублировать требования,
  контракты, задачи и решения между файлами; при изменении поведения обновляй
  профильный документ вместе с кодом.

### 2.1. Ветки и коммиты

Модель ветвления (проверяется CI, `.github/workflows/`):

- `main` — релизная ветка; прямые коммиты и push запрещены.
- `dev` — интеграционная; PR в `main` разрешён только из `dev` (`source-is-develop.yml`).
- Фича-ветки создаются от `dev` и вливаются обратно коротким PR.
  Прямые коммиты в `dev` — только для тривиальных правок, не пересекающихся с другими.

Имена веток: `<type>/<short-desc>` — латиница, kebab-case, нижний регистр.
`<type>`: `feature`, `fix`, `hotfix`, `chore`, `docs`, `refactor`.
Примеры: `feature/backend-core-wms`, `feature/ai-tools-design`, `feature/web-pwa-init`.

Коммиты — Conventional Commits (`feat:`, `fix:`, `docs:` ...), сообщение
на английском, императив. Перед коммитом обязательны `ruff check .` и
`ruff format --check .`. Коммит, push, PR — только по явной просьбе пользователя.
